# ADR-0001: Reuse 88emuPlayer for the VST3 instrument
status: accepted
date: 2026-11-08

## problem
Ableton Live needs a VST3 instrument with host MIDI, stereo audio and project persistence, while 88emuPlayer currently builds only its standalone JUCE wrapper.

## options considered
- A second processor or engine would duplicate the existing player and interface.
- Full CPU/DSP snapshots would require a new serialization contract across all emulated boards and processors.
- The existing JUCE processor and finite GS/LA configuration trackers already provide the required audio path and instrument configuration.

## decision
Enable the VST3 wrapper on the existing target and save versioned instrument configuration using the existing trackers.

## solution
Both wrappers link the same processor, emulation engine and editor. VST3 uses a private, non-saving PropertiesFile, the common ROM folder and the host's MIDI/audio callbacks. It creates no virtual MIDI endpoints. Standalone retains its existing on-disk configuration and device routing.

The host chunk stores a version, selected model, power, an allowlist of instrument/UI settings and bounded MIDI setup messages. JUCE wrapper state and audio device settings remain outside this chunk. GS restore messages are finite deltas from a fresh board; LA boards use their existing memory restore messages. Loading boots a fresh board and advances emulated time to complete paced setup before the first host note. Loading before audio preparation or without ROMs retains setup for later preparation. Host sample offsets, transport and engine latency pass through JUCE; offline sample-rate updates do not require an editor message loop.

## consequences
- Reopening a project restores tracked instrument configuration, not active voices, effect history, or a running CPU snapshot.
- Recognized SC-55mkII firmware has a read-only, validated part-memory view for actual front-panel bank/program and receive-channel assignments. Save reads that view without running the emulator ahead; memory-write revisions schedule host dirty notifications. Other physical panel edits still require Part Editor → Receive All. The MIDI-driven part editor is tracked directly.
- Private RPN/NRPN selector latches and transient performance gestures are not snapshots. Clips should send their controller setup.
- GS and MT-32/CM configuration is supported. MV-30, PRO-E, NU-10 and MIIG5 lack compatible full setup trackers; only player settings/model are saved for those boards.
- ROM/card files remain external assets at their existing paths; projects do not embed firmware. Instances share the ROM search location, while settings and emulated boards remain independent.
